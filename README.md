# hono-drizzle-boilerplate

Boilerplate for Cloudflare Workers API: Hono + `@hono/zod-openapi`, Drizzle ORM (Turso/libSQL), Better Auth. Deploys to Cloudflare Workers via Wrangler.

## Stack

- **Runtime**: Cloudflare Workers (`wrangler`)
- **Framework**: Hono + `@hono/zod-openapi` (OpenAPI-typed routes)
- **DB**: Drizzle ORM 1.0-beta, dialect `turso` (libSQL, `@libsql/client`)
- **Auth**: `better-auth` (email/password + `username` plugin), bcrypt password hashing, role field (`USER`/`ADMIN`)
- **Docs**: Scalar API reference at `/docs`, OpenAPI JSON at `/openapi` (auth routes merged in and re-tagged as `Auth`)
- **Lint/format**: Biome (tabs, double quotes)
- **Git hooks**: Husky + lint-staged (`format-and-lint:fix` + `check` on staged files) + commitlint (conventional commits)
- **Storage**: Cloudflare R2 bucket bound as `R2_BUCKET`

## Requirements

- Node >= 22
- pnpm 10.21.0 (see `packageManager`)

## Setup

```bash
pnpm install
cp .env.example .env      # fill in secrets
pnpm cf-typegen            # generate worker-configuration.d.ts from wrangler.json bindings
```

Required env vars (`.env` for local, Wrangler secrets for deployed envs):

| Var | Purpose |
|---|---|
| `BETTER_AUTH_SECRET` | Better Auth signing secret |
| `BETTER_AUTH_URL` | Base URL Better Auth issues/validates against |
| `TURSO_DATABASE_URL` | libSQL/Turso connection URL |
| `TURSO_AUTH_TOKEN` | Turso auth token |
| `ALLOWED_ADDITIONAL_ORIGINS` | Comma-separated extra CORS origins |

Config is loaded from `c.env` per-request in Workers, or from `process.env` when `NODE_ENV=local` (see `src/packages/constants/config.ts` and `src/packages/middlewares/config.ts`).

## Scripts

```bash
pnpm dev                # wrangler dev --remote
pnpm check              # tsc + wrangler deploy --dry-run
pnpm deploy             # wrangler deploy
pnpm format-and-lint      # biome check
pnpm format-and-lint:fix  # biome check --write
pnpm db <drizzle-kit-cmd>      # drizzle-kit against local env
pnpm db:stg <drizzle-kit-cmd>  # drizzle-kit against .env.stg
pnpm auth:generate       # regenerate src/database/drizzle/schemas/auth.ts from better-auth.config.ts
pnpm secrets             # wrangler secret bulk < secrets.json
```

Example: `pnpm db generate`, `pnpm db migrate`, `pnpm db studio`.

## Request flow

`src/app/index.ts` builds the app: `loadConfig` -> CORS -> `logger()` -> mounts `/healthcheck` and `/api` (from `src/app/route.ts`) -> `notFound`/`onError` -> `configDocs(app)` (adds `/openapi`, `/docs`).

`src/app/route.ts` mounts `^auth` (better-auth catch-all) at `/auth`, then applies `authenticate` to everything else under `/api`. Add new authenticated routes after the `.use(authenticate)` line; each module follows the `route.ts` (OpenAPI route defs) + `controller.ts` (handlers) + `dto.ts` pattern shown in `healthcheck`.

Use `authorize(...roles)` middleware for role-gated routes (`RolesEnum.ADMIN`, `RolesEnum.USER`).

## Auth

Better Auth is mounted directly as a Hono handler (`^auth` -> `/api/auth/*`). Most default Better Auth endpoints are disabled (`disabledPaths` in `src/packages/libs/auth.ts`) leaving sign-up, sign-in, sign-out, session, and username-related endpoints active. Users have a required `role` field; admin accounts can't be deleted (`beforeDelete` hook). Passwords hashed with bcrypt. Regenerate the Drizzle schema for auth tables with `pnpm auth:generate` after changing `better-auth.config.ts`.

## Database

Turso (libSQL) via `drizzle-orm`/`drizzle-kit` (`1.0.0-beta.15`). Config in `drizzle.config.ts`: schema files are `src/database/drizzle/schemas/index.ts` + `relations.ts`, migrations output to `src/database/migrations`. `$db()` (`src/packages/libs/db.ts`) is a lazily-initialized singleton client. Helpers: `withTransactionBuilder` for chainable transaction/exec, `buildConflictUpdateColumns` for upsert `ON CONFLICT` sets, `buildSqlFromRelationsFilter` / `fuzzy` for relational-filter and fuzzy-search SQL.

## Deployment

Configured in `wrangler.json`: entry `src/app/index.ts`, worker name `hono-drizzle-boilerplate`, R2 bucket binding `R2_BUCKET`, observability enabled. `pnpm check` runs `tsc` + a deploy dry-run before `pnpm deploy` actually ships.

## Git hooks / commit convention

Husky runs `lint-staged` on commit (`format-and-lint:fix` + `check` on staged `js/ts/cjs/mjs/json`), and commitlint on commit-msg using Conventional Commits (`@commitlint/config-conventional`).
